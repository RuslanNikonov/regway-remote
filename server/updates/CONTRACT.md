# RegWay Remote — контракт канала обновлений

Источник манифеста:

- `GET https://remote.regway.group/updates/manifest.json`
- `GET https://remote.regway.group/updates/manifest.json.sig`

`manifest.json` и `manifest.json.sig` скачиваются **тем же загрузчиком, что и файлы**: HTTP `Range` кусками не больше **16 КиБ**, с докачкой. Обычный GET без `Range` не используется.

Перед проверкой подписи клиент **отклоняет** манифест больше **15 КиБ**.

Клиент **сначала** проверяет подпись манифеста, и только потом хеш содержимого и поля `sequence`.

## Подпись

- Алгоритм: **ed25519** (`crypto_sign_ed25519`, detached).
- Подписываются **сырые байты** `manifest.json` (как скачаны, без нормализации JSON).
- `manifest.json.sig` — 64 байта подписи, кодировка **base64** (одна строка, без пробелов).
- Публичный ключ (base64, 32 байта): `8P4Zy7j96xjs3ObdDhOpUR6VQlxMCMeq73yzZwUv8RM=`
- `key_id`: `rw-2026-1`
- Манифест с другим `key_id` отклоняется.

CI подписывает секретом `UPDATE_SIGNING_KEY` (base64 приватного ed25519-ключа, 32-байтовый seed или 64-байтовый secret key). Ключ не пишется в лог и не кладётся в артефакты. Job, который собирает манифест кандидата, **падает**, если секрета нет. `manifest.json` и `manifest.json.sig` выгружаются артефактами; их полное содержимое (публичные данные) и `sha256sum` печатаются в лог CI.

## `sequence`

Целое неотрицательное число, монотонно растёт с каждой публикацией.

Клиент хранит последний **принятый** `sequence` и SHA-256 сырых байт того манифеста.

| Условие | Действие |
|---|---|
| `sequence` меньше принятого | отклонить |
| `sequence` равен принятому и SHA-256 совпадает | принять (идемпотентно, файлы не качать заново, если уже готовы) |
| `sequence` равен принятому и SHA-256 другой | отклонить |
| `sequence` больше принятого | принять после подписи |

Откат на более старую **версию клиента** разрешён только если в том манифесте `rollback_allowed` не `false`. Откат `sequence` назад всё равно запрещён правилом выше.

## Манифест

```json
{
  "version": "1.5.1",
  "sequence": 12,
  "key_id": "rw-2026-1",
  "rollback_allowed": true,
  "notes": "Кратко, что нового",
  "files": [
    {
      "os": "windows",
      "arch": "x86_64",
      "url": "https://remote.regway.group/updates/RegWayRemote-1.5.1-x86_64.exe",
      "sha256": "hex, 64 символа, нижний регистр",
      "size": 12345678,
      "filename": "RegWayRemote-1.5.1-x86_64.exe"
    }
  ]
}
```

Поля:

- `os`: `windows` | `macos`
- `arch`: `x86_64` | `aarch64`
- `sha256`: SHA-256 файла, hex
- `size`: размер в байтах, без сжатия на лету
- `rollback_allowed`: если `false`, клиент этой версии нельзя выбрать как цель отката

## Загрузка файла

1. Проверить, что выбранный файл подходит текущим `os`/`arch`.
2. Качать **кусками Range** не больше **16 КиБ** (`Range: bytes=start-end`, включительно).
3. Докачка после обрыва: продолжить с уже записанного смещения.
4. После полной загрузки сверить `size` и SHA-256. Несовпадение — удалить файл и ошибка.
5. Прогресс в UI: `Загрузка… N % · докачка после обрыва`.
6. Три неудачные попытки подряд: `Не удалось скачать обновление. Проверьте соединение` и кнопка «Повторить». Счётчик сбрасывается по «Повторить».

## Режимы

- **Авто**: проверка в фоне; установка **только после конца активного сеанса** (входящего и исходящего).
- **Вручную**: пользователь сам нажимает «Установить».

Доступное обновление:

- уведомление ОС;
- точка на пункте «Настройки».

## macOS

После загрузки: снять карантин `xattr -r -d com.apple.quarantine` с файла/бандла и перезапустить сервис.
